## 3. 能力边界

### 3.1 Fabric

当前是可真实提交交易的本地 Hyperledger Fabric 测试网络，不是演示账本；
但它仍是开发用 `fabric-samples/test-network`，不能描述为生产联盟链。

API 通过 `LEDGER_MODE=fabric` 使用 Fabric Gateway。建单、接单、揽收、运输
节点、异常、送达、签收和取消都已经映射到链码交易。

### 3.2 路线地图

当前地图使用 Leaflet 和 OpenStreetMap，能够显示城市及链上运输节点。虚线
表示节点之间的直线关系，显示数字不是道路里程。

当前尚未实现：

- 道路导航路线。
- 车辆实时 GPS。
- 预计行驶时长和实时路况。

### 3.3 Excel 运单导入

前端已经支持 `.xlsx`、`.xls` 和 `.csv`，包括模板下载、字段别名、逐行校验、
预览和批量提交。

后续仍可加强：

- 导出错误行和错误原因。
- 导入前重复运单识别。
- 大批量导入的任务进度、取消和失败重试。
- 后端批量事务或幂等键，避免网络中断后重复提交。

### 3.4 温控

温控不是实时传感器监测。当前流程是：

1. 发货方可选择设置允许温区。
2. 承运方在运输节点人工录入温度。
3. 链码比较温度和设定温区。
4. 越界时自动生成异常并保留当时记录。

尚未接入 IoT 温度传感器、设备证书和连续采样。未完成这些接入前，界面和
文档不得使用“实时温控监测”或“传感器自动上报”等表述。

## 4. 启动与验证

### 4.1 启动 Fabric

Docker Desktop 正常运行后，在项目根目录执行：

```powershell
pnpm fabric:up
```

启动脚本会准备本地 Fabric 依赖、通道、双组织 peer、CouchDB 和物流链码，
并生成被 Git 忽略的 `apps/api/.env.fabric`。

### 4.2 启动应用

正常方式：

```powershell
$env:ENV_FILE = (Resolve-Path ".\apps\api\.env.fabric").Path
$env:JWT_SECRET = "$([guid]::NewGuid())$([guid]::NewGuid())"
pnpm dev
```

如果需要分别启动 Go API 与前端，可使用两个终端：

```powershell
$env:ENV_FILE = (Resolve-Path ".\apps\api\.env.fabric").Path
$env:JWT_SECRET = "$([guid]::NewGuid())$([guid]::NewGuid())"
go run ./apps/api/cmd/server
```

另开终端启动前端：

```powershell
pnpm --filter @jixin/web dev
```

运行中的 watcher 进程不能作为 API 已启动的证据，必须实际访问端口和接口。

### 4.3 验证真实 Fabric 状态

```powershell

```

必须确认：

## 5. 敏感文件与清理边界

以下内容不得进入 Git：

- `apps/api/.env.fabric`
- Fabric 组织证书和私钥
- JWT 密钥
- 一次性签收码
- 本地生成的身份钱包或连接凭据

不要随意删除 Docker volumes。它们可能包含当前 Fabric 账本和 CouchDB 状态。
`pnpm fabric:down` 只应在明确需要停止或重建测试网络时执行，并应先确认是否
需要保留当前链上样本。

Windows Git Bash 启动 Fabric 时应使用：

```text
C:\Program Files\Git\bin\bash.exe --login
```

Docker socket 只排除 `DOCKER_SOCK` 的 MSYS 路径转换，不要改成全局禁用路径
转换。详细故障原因见 `docs/Fabric真实网络接入交接.md`。

## 7. 强制 Git 工作流

后续任何修改都遵循：

1. 先同步并检查 `main`。
2. 创建新的 `codex/` 功能分支。
3. 只在功能分支修改、测试和提交。
4. 展示改动供用户审核。
5. 得到明确批准后，使用 `git merge --no-ff` 合并到 `main`。
6. 推送合并提交并验证远端 `main` 可达。
7. 只有确认合并提交已推送后，才删除已合并分支。

不得直接在 `main` 实现功能，不得默认使用快进、squash 或 rebase 代替明确的
双父合并提交。
