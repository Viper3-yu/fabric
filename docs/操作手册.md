# 迹信操作手册

本手册面向需要运行和演示本系统的使用者，按业务流程逐步说明操作方法。环境安装与部署细节见 [README](../README.md)，部署到 Ubuntu 虚拟机见 [Ubuntu虚拟机部署指南](Ubuntu虚拟机部署指南.md)。

## 1. 启动系统

以 Windows 为例（Linux/macOS 命令一致，环境变量写法见 README）：

```powershell
# 1. 手动启动 Docker Desktop，等其就绪
# 2. 启动区块链网络并部署链码（首次先执行 pnpm fabric:bootstrap）
pnpm fabric:up

# 3. 启动前端与 API
$env:ENV_FILE = (Resolve-Path ".\apps\api\.env.fabric").Path
pnpm dev

# 4. 写入 12 条演示运单（可选，幂等可重复执行）
pnpm seed
```

启动完成后：

- 浏览器打开 <http://localhost:5173>；
- 打开 <http://127.0.0.1:3001/api/network>，返回 `"mode":"fabric"`、`"status":"ok"` 即表示已连接真实区块链。

## 2. 账号与角色

| 账号       | 角色   | 能做的事                                       | 所属组织 |
| ---------- | ------ | ---------------------------------------------- | -------- |
| `shipper`  | 发货方 | 创建运单、取消未接单运单、发起跨组织交接       | Org1     |
| `carrier`  | 承运方 | 接单、揽收、录入节点、处理异常、送达、确认交接 | Org2     |
| `receiver` | 收货方 | 使用一次性签收码确认收货                       | —        |
| `auditor`  | 审计   | 只读查看运单与链上证据                         | —        |

账号密码由 `apps/api/.env.fabric` 的 `APP_PASSWORD_*` 配置。本机开发使用演示密码 `shipper` / `shipper123` 等四组（账号与密码同名规则），仅限本机和课堂演示，不得用于公网部署。

## 3. 完整业务流程（建单到签收）

### 步骤 1：发货方创建运单

1. 用 `shipper` 登录，进入「创建运单」。
2. 填写货物名称、收发地址、联系人，可选设置温控范围（例如 2℃～8℃）。
3. 提交后系统返回业务运单号和 **6 位一次性签收码——只显示这一次，立即保存**。链上只保存签收码的 SHA-256 摘要，不保存明文。

### 步骤 2：承运方接单、揽收

1. 换 `carrier` 登录，在运单列表找到该运单（状态：待接单）。
2. 依次执行「接单」「揽收」。每一步都是一笔 Fabric 交易，响应和页面都会显示交易 ID、提交组织（Org2MSP）和账本时间。

### 步骤 3：运输节点与温控异常

1. 承运方在运单详情录入运输节点：地点、备注、可选温度读数。
2. 录入超出温控范围的温度（例如温区 2～8℃ 录入 12℃）时，智能合约**自动判定越界**并写入异常事件，运单进入异常状态。
3. 处理异常后运单恢复运输；异常记录保留在时间线上，不可删除。

### 步骤 4：确认送达

承运方在目的地执行「确认送达」，可附带送达凭证摘要（SHA-256），供后续核验。

### 步骤 5：收货方签收

1. 换 `receiver` 登录，找到待签收运单，输入签收码。
2. 可以先故意输错一次：链码比对摘要失败，签收被拒绝。
3. 输入正确签收码后运单进入「已签收」。签收码一次性使用，签收后失效。

### 步骤 6：公开查询与记录核对

1. 退出登录（或直接另开浏览器窗口），打开 <http://localhost:5173/track>，输入运单号。
2. 公开页展示脱敏轨迹：联系人姓名与手机号打码、详细地址隐藏，时间线包含异常及处理记录，每个事件带交易 ID 与提交组织。
3. 打开「记录核对」页（/verify），输入运单号与文件核对编号，可校验文件是否与上链存证一致。

## 4. 批量导入演示运单

以发货方登录 → 运单管理 → 批量导入 → 下载演示数据（`apps/web/public/demo-shipments.csv`，含医药冷链、常温电子设备、冷冻海产三条）→ 选择文件 → 检查预览 → 提交导入。

注意：导入只创建待接单运单，后续流程仍由承运方、收货方逐步推进；导入结果页需立即下载并保管一次性签收码。

## 5. 运输控制塔与双边交接

控制塔后端为 `apps/tower-api`，与本系统共用同一条链码、同一本账本：

```bash
# 终端 1：Org1 实例（发货方侧，端口 8080）
cd apps/tower-api && GOWORK=off ENV_FILE=../../apps/api/.env.fabric go run ./cmd/server

# 终端 2：Org2 实例（承运方侧，端口 8082）
GOWORK=off ENV_FILE=../../apps/api/.env.fabric TOWER_ORG=2 PORT=8082 go run ./cmd/server
```

前端经 Vite 代理访问（`/lianyun-api`、`/lianyun-org2-api`），开发模式下直接可用：

- **控制塔**（/app/control-tower）：输入运单号（如 `JXSEED0004`）查看节点时间线、路线示意与温度曲线；响应标注 `dataSource`（未接 MySQL 时为 `demo`）。
- **双边交接**（/app/handovers）：用 `shipper` 登录发起交接，再换 `carrier` 登录确认。发起方自行确认、重复确认都会被链码拒绝——这是双组织权限隔离的现场演示点。
- **数据源设置**（/app/settings/integrations）：查看与切换遥测数据源。

## 6. 预置演示运单

`pnpm seed` 写入 12 条覆盖全部状态的运单（正常签收、温度异常、待接单、已取消等），编号 `JXSEED0001`～`JXSEED0012`，场景清单见 [演示数据说明](DEMO-GUIDE.md)。

## 7. 常见问题

| 现象                       | 处理                                                                                                    |
| -------------------------- | ------------------------------------------------------------------------------------------------------- |
| 登录失败但密码正确         | 按「Docker 是否在跑 → `docker ps` 是否 7 个容器 → `/api/network` health → 3001 端口是否有残留进程」排查 |
| `fabric:up` 后账号密码失效 | 不会：密码行会自动保留。若是新机器，需重新配置（证书不可跨机拷贝）                                      |
| 页面运单是旧的             | 重建过网络后账本是新的，重新执行 `pnpm seed`                                                            |
| 控制塔 503                 | 对应端口的 tower-api 实例没启动，或该运单在 MySQL 模式下无路线数据                                      |
| 公开查询 404               | 运单号不存在或未上链，先确认 `pnpm seed` 已执行                                                         |

更多运维命令（停止网络、查看日志、更新部署）见 README「常用命令」与 [Ubuntu虚拟机部署指南](Ubuntu虚拟机部署指南.md) 第 8 节。
