# 演示流程

本流程用于录屏和课堂展示，不替代答辩 PPT。

## 演示前准备

1. 运行 `pnpm install` 和 `pnpm build`。
2. 无 Docker 时使用演示账本启动；有 Docker 时优先运行 `pnpm fabric:bootstrap`、`pnpm fabric:up` 并切换到 Fabric 模式。
3. 在浏览器打开前端首页，确认页面顶部账本模式显示符合预期。
4. 记下创建运单后生成的一次性签收码，后续签收需要使用。

## 建议演示顺序

1. 公开查询页：输入不存在的运单号，展示错误和空结果处理。
2. 发货方登录：创建一票带温控范围的运单，说明签收码只显示一次。
3. 交易证据：展示建单交易 ID、提交组织和账本模式。
4. 承运方登录：依次接单、揽收、添加正常运输节点。
5. 异常存证：录入越界温度，展示系统自动进入异常状态和异常计数。
6. 异常处理：提交处理说明后恢复运输，原异常仍保留在时间线。
7. 送达：提交送达位置和凭证摘要，状态进入待签收。
8. 收货方登录：先输入错误签收码，展示链码拒绝；再输入正确签收码完成签收。
9. 公开验真：退出登录，通过运单号查看脱敏轨迹、最终状态和完整性结论。
10. 若使用 Fabric 模式，打开证据详情，指出真实交易 ID、Org1MSP/Org2MSP 和区块链时间。

## 讲解重点

- 前端不能任意修改状态，错误状态转换由 API 和智能合约共同拒绝。
- 演示账本只用于预览，页面不会把它描述成真实上链。
- Fabric 模式下，发货和签收使用 Org1 身份，承运动作使用 Org2 身份。
- 链上保存的是必要业务字段和摘要，不保存签收码明文或完整个人隐私。
