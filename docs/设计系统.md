# 迹信设计系统

## 设计方向

迹信是一套可信物流取证控制台。界面需要让用户快速判断货物在哪里、当前责任属于谁、下一步需要做什么，以及一条记录是否能够被复核。

整体语言来自运输清单、交接单和链上回执，而不是科技展厅。公开服务负责解释价值，业务工作台负责高密度操作，证据模块负责建立可验证感。

## 设计原则

1. 事实先于装饰。路线必须带节点、状态或时间，不能只是背景曲线。
2. 动作先于统计。异常、待处理和当前责任始终早于总量展示。
3. 证据保持克制。交易 ID、摘要、账本模式和时间戳使用等宽数字，不使用霓虹、字符滚动或持续发光。
4. 隐私边界可见。公开信息、脱敏信息和链下原件必须通过文案与层级明确区分。
5. 几何保持统一。业务表面使用 8px 小圆角，控件使用 4px 圆角，胶囊只用于状态标签。

## 视觉基调

- 画布：温和的纸张灰白，避免纯白后台的生硬感。
- 文字：近墨黑与矿物灰，形成清晰扫描路径。
- 主色：森林绿，只用于主动作、焦点、已验证路径和品牌标记。
- 证据面板：深墨绿，用于链路、账本和关键回执。
- 语义色：蓝色表示运输状态，橙色表示等待，红色表示异常；语义色不能替代主操作色。
- 深度：普通表面依靠 1px 边框和色差，不堆叠卡片阴影；只有浮层和关键影像可使用单层阴影。

### 暗色模式

系统跟随 `prefers-color-scheme` 提供暗色画布，令牌与浅色模式一一对应：

- 画布：深墨绿灰 `#0d1411`，表面逐级抬升 `#111a16` / `#16211c` / `#1d2a24`。
- 主色与信号：亮化薄荷绿 `#6acba0`，只用于焦点、已验证路径和状态强调。
- 文字：雾白 `#edf3f0` 与灰绿 `#aab7b0`，保持清晰的扫描路径。
- 证据面板与深色侧边栏延续深墨绿底，内部细线使用 `rgba(229, 243, 235, 0.18)`。
- 语义色在暗色下同步提亮一档，但仍不得替代主操作色。
- 暗色模式不新增霓虹效果，不改变几何、字体与动效阶梯。

## 字体

- 正文与后台：内置 `Noto Sans SC Variable`，搭配 `Manrope Variable` 处理拉丁字符和数字，保证 Windows 与 Ubuntu 显示一致。
- 公开叙事标题：使用 `Noto Serif SC Variable`，形成类似档案与交接凭证的编辑感；后台标题继续使用无衬线体。
- 业务数字：运单数量、时间和指标使用 Manrope 的等宽数字特性，不再统一套用编程字体。
- 交易哈希、区块摘要和需要逐字符核验的标识才使用 `Cascadia Mono`、`SFMono-Regular` 或 `Consolas` 回退。
- 标题使用 600 字重和舒展行高，中文不使用极端负字距；移动端短标题按语义成行，不允许单字掉行。

## 影像

- 公开页主视觉为蓝调时刻纪实摄影（`night-route.jpg`，Pexels 28380982 立交桥车流）：hero 承载影像并以重遮罩保证文案对比度，登录品牌板与运输清单证据面板叠暗调底图，其余区域回到纸面网格。残余的路线与凭证图形（`route-window.svg`）只作局部点缀。
- 纪实摄影推荐蓝调时刻、湿地面、矿物灰和森林绿信号灯，保留工业现场质感；画面不得出现人脸、可读文字与品牌标识。
- 路线图层必须对应真实业务节点，不能使用科幻 HUD、全息面板、霓虹光轨或无业务含义的扫描线。
- 图片内部说明采用“节点位置、确认结果、账本时间”三层信息，保持简短且可核验。
- 生成资源以版本化文件名保存（如 `*-v2.svg`），不再被引用的旧版本及时移除。

## 网格与布局

- 基础单位：8px。
- 桌面：16 列，内容轴最大 1312px，左右 gutter 32px。
- 平板：8 列，左右 gutter 24px。
- 移动：4 列，左右 gutter 16px。
- 导航最高 72px，保持单行。
- 页面标题、说明和主动作共享水平基线。
- 后台标题左对齐；只有查询单任务、空状态、成功状态和关键核验结论可以居中。

## 组件

### 导航

导航固定在页面顶部，使用近白实色和底部分隔线，不使用厚阴影或大面积毛玻璃。当前项以森林绿下边线和文字强调。

### 按钮

- 主按钮：森林绿实底。
- 次按钮：透明底与墨绿边框。
- 危险按钮：仅在取消和异常操作中使用红色。
- 按钮不做明显抬升或弹跳；按下时最多向下移动 1px。

### 表单

输入控件使用清晰的 1px 边框和近白底色。聚焦时显示 2px 森林绿焦点环。标签始终可见，不只依赖占位文字。

### 表面

普通卡片不使用阴影。相邻指标使用连续网格而不是重复悬浮卡片。证据面板可以使用深墨绿底色，但内部信息仍以细线划分。

### 状态

状态标签可以使用胶囊几何。装饰性圆点禁止出现；网络在线圆点必须配合可读状态文字。

### 路线

路线首次进入时绘制一次，随后静止。节点必须对应创建、交接、运输、异常或签收等真实含义。当前位置使用实心节点，未到达位置使用空心节点。

## 动效

业务动效表达三件事：路径连接、节点确认、状态切换。公开叙事页额外允许电影感叙事动效（滚动钉住、逐词 scrub、跑马灯），用于建立产品的沉浸气质；业务工作台不使用叙事动效。

- 即时反馈：80ms。
- 微交互：120ms。
- 控件状态：180ms。
- 面板进入：240ms。
- 页面进入：360ms。
- 公开页首屏：520ms。
- 公开页叙事动效由 gsap 驱动（hero 交错入场、清单面板钉住与卡片滑入、逐词 scrub、跑马灯）。
- 后台页面最长动效不超过 240ms，列表与表格行不做逐条入场。
- 全线不使用磁吸按钮、3D 倾斜和持续呼吸。
- `prefers-reduced-motion: reduce` 下直接显示最终状态并停止跑马。

## 响应式

- 公开页桌面采用文字与物流影像两栏；移动端先展示查询任务，再展示约 264px 高的证据影像。
- 后台概览桌面采用稠密两列；移动端顺序为待处理、核心指标、网络证据、最近运单。
- 长表单移动端使用清晰的底部操作区，触控目标不小于 44px。
- 表格在移动端转为业务卡片，不进行水平压缩。

## 禁止事项

- 不混入多套品牌蓝、荧光绿或紫色渐变。
- 不使用厚重圆角、层层阴影和玻璃拟态。
- 不将所有标题居中，不将所有内容放进独立卡片。
- 不让绿色和红色同时承担主按钮角色。
- 不在数据更新时重复播放整页揭幕动画。
- 不使用没有业务内容支撑的纯装饰光点、扫描线和漂浮动画（跑马灯承载物流闭环阶段文案，属内容动效）。
