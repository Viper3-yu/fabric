# 迹信项目介绍

## 项目概述

迹信是一套基于 Hyperledger Fabric 的可信物流追踪系统。系统围绕发货、接单、揽收、运输、异常处理、送达和签收构建完整业务链路，将每次关键交接记录为区块链交易，为物流参与方提供责任清晰、可核验、不可由单方事后修改的运输证据。

## 解决的实际问题

传统物流跟踪通常由单一平台维护。轨迹发生缺失、延迟录入或争议时，发货方、承运方和收货方难以证明某个节点由谁在何时提交。温控货物还存在异常证据分散、图片与单据真假难验证的问题。

迹信通过以下能力解决这些问题：

- 关键节点由对应 Fabric 组织身份提交，并记录交易 ID 和 MSP。
- 状态流转由智能合约约束，不能跳过揽收直接签收，也不能重复签收。
- 温度越界由智能合约自动判定并记录异常，异常记录不能删除。
- 文件原文不直接上链，只保存 SHA-256 摘要，兼顾隐私和验真。
- 收货方使用一次性签收码闭合流程，链上只保存签收码摘要。
- 公开查询页返回脱敏轨迹，便于客户和审计人员核验。

## 应用场景

系统适合中小物流公司、企业内部调拨、冷链样品运输和需要交接凭证的高价值货物运输。课程演示使用双组织 Fabric 测试网络，Org1 代表发货侧，Org2 代表承运侧。

## 产品方案

系统提供四类角色：发货方创建和取消未接单运单，承运方负责接单、揽收、节点更新、异常处理和送达，收货方输入一次性签收码确认收货，审计访客通过公开查询查看脱敏轨迹和证据。

完整流程如下：

1. 发货方填写收发地址、货物和温控要求并创建运单。
2. 承运方接单并揽收。
3. 承运方持续写入物流节点；温度越界或人工异常会进入异常状态。
4. 承运方处理异常后恢复运输，并在目的地提交送达凭证摘要。
5. 收货方输入一次性签收码完成签收。
6. 任意访客使用运单号查看脱敏轨迹和验真结论。

在运单业务之上，系统还提供运输控制塔：包裹登记、物流单元装箱/拆箱和跨组织交接确认并入同一条链码、同一本账本。一笔跨组织交接由发货方发起、承运方确认，是两笔独立的链上交易，发起方无法自确认；控制塔页面按运单展示节点时间线、路线与温度曲线，MySQL 遥测作为可选链下数据源。

## 技术开发方案

- 浏览器端：React、TypeScript、Vite、IBM Carbon。
- Web 服务：Go 标准库 HTTP、手写严格校验、HMAC-SHA256 JWT。
- SDK：Hyperledger Fabric Gateway Go SDK 和 gRPC。
- 智能合约：Go、Fabric Contract API。
- 区块链：Hyperledger Fabric 2.5 LTS 双组织测试网络、Raft orderer、CouchDB。
- 测试：Go `testing`/`httptest`、Vitest、Testing Library。

API 通过可替换的 Ledger Adapter 访问账本，只连接真实 Fabric 网络：业务请求使用 Fabric Gateway 提交交易；单元与闭环测试使用文件型测试替身（`apps/api/internal/ledger/fake`）模拟链上状态机，不需要 Docker，也不会把测试结果描述成真实上链。

## 主要创新

### 责任交接链

每个业务事件带有调用者 MSP、证书身份、Fabric 交易时间和交易 ID，可明确交接责任。

### 签收码摘要

明文签收码只展示给业务用户，链上保存摘要。签收时由智能合约计算摘要并比对，避免在账本中泄露明文。

### 温控异常自动存证

运单可设置温区。运输节点录入温度后，智能合约在越界时自动生成异常事件，减少人为漏报。

### 证据哈希验真

送达图片或业务单据可以在应用侧计算摘要并上链。后续再次计算原文件摘要即可判断文件是否与当时存证一致。

## 最终成果

项目交付包括：React 前端（工作台、运单管理、创建运单、运单详情、公开查询、记录核对、登录）、Go 后端 API、运输控制塔后端与三个控制塔页面（控制塔、双边交接、数据源设置）、Go 智能合约（运单状态机与包裹/物流单元/双组织交接）、Fabric 测试网络脚本、设计方案与运行文档、自动化测试（前端组件、API 闭环、链码状态机，以及真实链上闭环测试）。自动化测试覆盖链码状态机、API 闭环和前端组件；界面联调需按 README 连接真实 Fabric 测试网络。
