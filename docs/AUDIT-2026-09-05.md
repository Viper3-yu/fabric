## 仍应优先优化的架构问题

1. **P1 统一权限入口**：Apache 的两个链运代理仍独立于主 API 的 cookie 鉴权，同一演示用户能使用两个服务身份。应由主 API 验证会话、角色、运单参与者后转发，桥接后端限制内部访问；不能只隐藏按钮。当前本机访问限制是部署边界，不是业务授权。
2. **P1 统一运单标识**：主项目 `JXSEED*` 和链运 `YT*` 属于不同链码。建议主运单作为权威实体，建立显式 ID 映射和事件投递记录，带幂等键、失败重试及对账。避免前端双写两套链码造成半成功。
3. **P1 合约级交接约束**：链运确认目前校验“不同于发起组织”，应进一步限定指定接收组织；发起时校验运单存在、参与者和有效网点。需补独立合约测试后升级链码，本轮未改变链上定义。
4. **P2 异常闭环精确关联**：本轮按网点和时间关联解除记录，是现有字段支持的保守改进；后续应贯通 `RelatedID`，实现一条异常对应一条处理记录。延误目前没有关闭工作流，保留待核查。
5. **P2 遥测与 GIS**：数据库仍为示例读数；真实偏航需要计划道路折线、坐标系和距离阈值。需加入设备身份、采集时间、去重和断流告警。
6. **P2 构建与维护**：工作区有多份源码副本；以后以 `github-fabric` 为维护源，WSL 仅部署。Carbon 全量 CSS 和中文字体造成较大构建资产，可后续按组件/字重收敛。

## 验证范围

新增后端测试覆盖空遥测不伪造、数据库错误不隐藏、异常解除的网点/时间边界；前端测试覆盖请求乱序和失败后清空数据。运行既有前端与 Go 测试、类型检查构建，并在本机浏览器检查页面。本轮未执行 Fabric 链码升级或迁移两套运单数据。

前端 24 项测试通过，主项目 Go 测试和链运后端测试通过，前端类型检查及构建通过。浏览器已验证中文状态、采集时间、交易时间倒序、缺失运单清空旧卡片。缺失运单返回可读的 404 提示，其他控制塔查询故障返回 503，底层错误仅保留在服务日志。2026-09-06 收尾检查确认本机服务正常，控制塔返回 MySQL 来源和两条待核查延误。
