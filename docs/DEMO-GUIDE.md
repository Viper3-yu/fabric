公开查询首页提供四个快捷入口，查询结果来自 API 和 Fabric，不是硬编码轨迹。样例步骤在播种时连续提交，时间表示实际提交时间，不模拟数天的真实运输时间。样例上的文件摘要对应合成文本，不代表已存储的实际附件。

控制塔仍使用独立链运数据源（例如 YT20260001），不能把 JXSEED 运单误当成该数据源中的运单。

## 演示文件导入

以发货方登录 → 运单管理 → 批量导入 → 下载 3 条演示数据 → 选择下载的 CSV → 检查预览 → 提交导入。

文件也位于 `apps/web/public/demo-shipments.csv`，包含医药冷链、常温电子设备、冷冻海产三种温控要求。联系电话和地址为演示占位，请勿实际联系。预计送达日期为 2026-12-31，跨年演示请先更新。

CSV 导入只创建待接单运单，不伪造后续事件。每次导入会新建运单，不具备重复文件去重功能。导入完成立即下载结果并保管一次性签收码；后续由承运方接单、更新轨迹，收货方确认。

## 页面资源失败的恢复

“重新加载页面”执行整页刷新，从而重新请求失败的懒加载模块；返回物流查询也执行完整导航。WSL 停机时请先启动本机服务。Apache 对入口 HTML 禁用缓存，对带哈希的静态资源长期缓存，缺失资源返回 404 而非 HTML。部署保留旧静态资源并最后原子替换入口，保护已打开的页面。

## 定位轨迹演示

运单 `JXSEED0004` 的详情页使用 OSRM 基于 OpenStreetMap 生成的杭州至南京道路路线。路线已经抽样并固化在 `demo-road-routes.ts`，答辩现场无需调用道路规划 API。蓝线代表已经上报的演示定位点，灰色虚线代表后续计划路线，地图显示最近位置和最近业务更新时间。

这些坐标用于展示“接收定位上报后如何查看物流”，不表示真实车辆、实时速度或现场设备。真实上线仍需车辆 GPS 设备或承运商接口持续上报坐标，并为定位数据增加设备身份、采样时间和质量校验。定位通常保留在链下，关键事件或批次摘要再按业务策略写入 Fabric。

数据来源：OSRM Route Service / OpenStreetMap，遵循 OpenStreetMap 署名要求。若改用高德，高德 Web 服务需申请 Key，地图 JS API 还需 Web Key 和安全密钥，并注意 GCJ-02 坐标转换。
