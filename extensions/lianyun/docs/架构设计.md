# 系统架构设计

## 1. 目标

系统不是单企业查询工具，而是一个由货主（Org1MSP）和承运/仓配方（Org2MSP）共同维护的可信物流协同系统。链上记录多方共同认可的事实；链下保存高频、敏感和大体量数据。

## 2. 核心闭环

创建运单 → 包裹装箱 → 发起交接 → 接收确认 → 到站/离站 → 异常处理 → 签收凭证 → GIS 风险审计。

物流单元可以表达 `运单 → 包裹 → 箱/托盘` 的聚合和拆分。每一个包裹可以反向查询曾经所属的箱、经历过的网点和交接责任段。

## 3. 分层

| 层       | 技术                         | 职责                                    |
| -------- | ---------------------------- | --------------------------------------- |
| 表示层   | PHP、Bootstrap 5、Leaflet    | 控制塔、GIS、表格、时间线               |
| 服务层   | Go、Gin、JWT                 | 认证、业务编排、风险计算、审计          |
| 区块链层 | Fabric Gateway、Go chaincode | 多组织交易、状态机、不可篡改证据        |
| 数据层   | MySQL                        | 用户、网点、路线、GPS、遥测、文件元数据 |
| 遥测插件 | GPS/CSV/MQTT Adapter         | 归一化数据、风险检测、摘要存证          |

## 4. 插件约定

每个遥测插件实现四步：`ingest`（接收原始数据）、`validate`（校验）、`summarize`（生成区段摘要）、`anchor`（将哈希和异常摘要上链）。

- GPS：轨迹点存 MySQL；根据计划路线和电子围栏判断偏航、离站、到站。
- 温湿度：原始 CSV 存 MySQL；曲线和阈值在前端展示；最小值、最大值、超阈次数与文件哈希上链。
- 插件产生的是“风险提示”，最终责任以交接记录、组织身份、异常处置和签收凭证综合确认。

## 5. GIS 风险定位

GIS API 将 Fabric 事件中的 `hubCode` 与 MySQL 中网点经纬度拼接。每个运输段的责任从上一条已确认交接开始，到下一条已确认交接或到站事件结束。

| 规则                    | 输出             |
| ----------------------- | ---------------- |
| 实际到达晚于计划时间    | 延误风险段       |
| 连续 GPS 点远离计划折线 | 路线偏离风险段   |
| 发生 EXCEPTION 事件     | 异常节点和异常段 |
| 交接申请超时未确认      | 待确认交接       |
| 文件哈希不一致          | 凭证篡改风险     |

## 6. 前端设计原则

采用企业物流控制塔而非炫光/渐变式 AI 仪表盘。深蓝导航、浅灰工作区、紧凑数据表格、地图为主视觉。禁止 emoji、玻璃拟态、无意义大卡片和夸张营销文案。
